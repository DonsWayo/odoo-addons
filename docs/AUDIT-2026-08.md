# Git Hosting audit — August 2026

Scope: the whole `dw_git` module at commit `d2c7cbf` — models, controllers,
security, data files, manifest, and the test suite.

## Summary

The suite reported **54 tests, 0 failures**. It also never executed the code
paths that were broken. Twelve of the defects below are crashes or
authorisation failures on the first call to a public entry point; every one
of them was reachable from the UI or the network.

The gap was structural, not accidental:

- `tests/test_integration_git.py` seeded repositories with
  `shutil.copytree()` instead of `_init_git_repo()`, so the one method that
  creates a repository on disk had never run under test.
- No test issued an HTTP request to `/api/git/*` or the portal routes, so
  eight endpoints that raise on line 1 looked healthy.
- No test attached an `res.groups` to a repository, so a compute that reads a
  field Odoo 19 renamed was never evaluated.
- No test authenticated as user B against user A's repository, so the Smart
  HTTP layer's authorisation hole stayed invisible.

Test count after the audit: **105 tests, 0 failures**, with one regression
test per defect in `tests/test_regressions.py`.

## Findings

Severity: **S1** exploitable or data-destroying · **S2** feature broken for
all users · **S3** correctness/robustness · **S4** hygiene.

### S1 — Security

| # | Finding | Evidence |
|---|---|---|
| 1 | **Any valid PAT unlocked any repository.** `_get_repo()` discarded the Basic-auth username, looked the password up as a PAT globally, and returned the repo without asking whether the token's *owner* could access it. `repository_ids` is documented "empty = all accessible repositories" but was implemented as "empty = all repositories" — and empty is the default. Bob could clone and push to Alice's private repo with his own token. | `test_foreign_pat_cannot_read_private_repo` returned `200`, expected `401` |
| 2 | **Deploy keys and webhooks were world-readable to employees.** Their only `ir.rule` named `group_git_manager`. A record rule bound to a group does not apply to non-members — who then match *no* rule and are unrestricted. `ir.model.access.csv` grants `base.group_user` read (and write/create on deploy keys). Both models stored a plaintext credential. | `test_employee_cannot_read_foreign_deploy_key` |
| 3 | **`git.pr.file`, `git.pr.review`, `git.webhook.delivery` had no record rules at all** — review bodies, diff patches and delivery payloads of every private repository were readable by any employee. | `test_employee_cannot_read_foreign_pr_review` |
| 4 | **Raw tokens were stored forever.** `git.personal_access_token.token` and `git.deploy_key.token` kept the secret in a column next to its SHA-256 hash. The form view says "This token will not be shown again"; the database disagreed. | `test_pat_raw_token_not_persisted` |
| 5 | **Branch merge restrictions were never enforced.** `git.branch.can_user_merge()` existed and was called from nowhere; `action_merge()` checked approvals but not the restricted-merge user list. | `_compute_mergeable` / `action_merge` review |

| # | Finding |

## Not fixed — deliberately

These are missing features, not defects to patch silently. See
[LIMITATIONS.md](LIMITATIONS.md).

- **Webhooks are recorded but never sent.** `_process_event()` writes a
  `git.webhook.delivery` row with `status='pending'`; no cron, queue or HTTP
  client ever delivers it. Building one means choosing timeouts, retry/backoff
  and — because the target URL is user-supplied — an SSRF policy. That is a
  design decision, not a bug fix.
- **There is no SSH transport.** `clone_url_ssh` is computed and displayed,
  but the module ships no SSH server; only Smart HTTP works.
- **Branch protection is not enforced on `git push`.** Deciding it requires
  parsing ref updates out of the pack, which the controller does not do.
  Protection currently applies to merges performed through Odoo.
- **`require_signed_commits`, `require_linear_history`,
  `require_status_checks` and `max_file_size` are stored and never read.**
